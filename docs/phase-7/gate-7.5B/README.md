## Prepared architecture

Browser → temporary Netlify HTTPS origin → same-origin `/api/*` proxy → Render
FastAPI → dedicated synthetic PostgreSQL 16. Uploaded bytes use a local absolute
artifact directory, initially ephemeral. Netlify does not host FastAPI.

Direct browser requests to Render would conflict with relative frontend URLs,
`credentials: same-origin`, non-credentialed CORS and Lax session cookies. The
proxy preserves these semantics without broadening CORS or changing frontend
fetch behavior. Auth origins must contain the exact Netlify HTTPS origin.
Secure HttpOnly `__Host-` cookies, CSRF tokens and ownership checks remain intact.
Actual cookie forwarding, Origin/Referer forwarding, HTTPS detection and cache
behavior through both platforms are NOT VERIFIED by local source checks.

The Netlify build runs `python3 scripts/generate_netlify_redirects.py`. It validates
`DANDOONJAN_BACKEND_URL` as an exact HTTPS origin without credentials, whitespace,
path, query or fragment, then writes only `frontend/_redirects`. No real Render
URL is invented and netlify.toml is never mutated during build. Rules are ordered:

1. `/api/*` → backend `/api/:splat`, forced proxy.
2. `/ui/*` → published root assets, covering CSS/JS/images and nested assets.
3. `/case/*` → `/index.html` presentation fallback.

There is no catch-all fallback that hides missing API endpoints as HTML. `/`
serves the existing index. Dossier API paths already match and remain unchanged.
Generated redirects are build output, not an artifact generated by this gate.
The Python build runtime and effective hosted redirects still require platform
verification. Netlify proxy processing has a documented 26-second timeout;
Render cold starts and synchronous processing must be evaluated before extending
acceptance beyond this gate's infrastructure scope.

## Explicit staging safety contract

`DJ_ENVIRONMENT=staging` is recognized by deployment preflight. It requires:

- PostgreSQL using `postgresql+psycopg`, server major 16 and current Alembic head.
- Auth foundation enabled, exact HTTPS auth origins, empty CORS list.
- `DJ_AI_PROVIDER=mock`, `DJ_AI_MODEL_NAME=mock-evidence-v1`.
- `DJ_LIVE_PROVIDER_ENABLED=false` and
  `DJ_LOCAL_SYNTHETIC_ACCEPTANCE_ENABLED=false`.
- No nonempty `DJ_OPENROUTER_API_KEY` or `DJ_OPENAI_API_KEY`.
- `DJ_REQUIRE_CLINICIAN_REVIEWED_KNOWLEDGE_PACK=true`.
- An existing absolute writable artifact directory and packaged frontend assets.
- Launcher validation of finite literal trusted proxy peers and valid `PORT`.

Configuration rejection happens before database/storage checks. Preflight never
constructs a provider, makes a provider request or runs migrations. Production
retains its original live OpenRouter/key/model and reviewed-pack requirements;
staging does not replace or weaken those guards.

No clinician-reviewed Knowledge Pack exists. The seeded DEVELOPMENT pack remains
`NOT_CLINICALLY_VALIDATED`; enforcement refuses it. Clinical processing refusal is
expected, including Demo processing: the existing Demo gateway does not authorize

Initial acceptance covers health, routing, secure auth, synthetic case/dossier

disabled. Existing Dockerfile uses Python 3.11 and the preflight launcher. It
creates neither a database nor a disk. No provider keys are declared.

Account-specific values must be supplied later:

- `DJ_DATABASE_URL`: approved synthetic PostgreSQL 16 URL, kept on Render only.
- `DJ_AUTH_ALLOWED_ORIGINS`: JSON array of exact Netlify HTTPS origins.
- `DJ_TRUSTED_PROXY_PEERS`: verified finite literal Render ingress IPs; no wildcard

- Netlify receives only the HTTPS backend origin, never database/provider secrets.

inspect the target database/schema and provenance; unknown deployed state is a
Stop Condition. Rehearse fresh and populated synthetic data locally, preserve

Preflight checks revision and version read-only; it does not prove full schema
integrity or perform backup/restore. No hosted migration was run in this gate.

## Ephemeral storage and access limitations

The owner permits ephemeral artifacts for infrastructure-only staging. A storage
probe proves only current readability/writability, never persistence or mounting.
Bytes can disappear on restart/redeploy while PostgreSQL rows survive. Acceptance
excludes durable uploads, evidence recovery/reprocessing after restart, preserved
artifact history, backup/restore and durable-storage readiness. Use only disposable
synthetic uploads; do not erase surviving rows/history to conceal missing bytes.

Render Free cannot attach a persistent disk. Durable artifacts require later
owner cost approval for paid compute/disk or another separately reviewed storage
solution. Free PostgreSQL is time-limited; availability/version/account eligibility
must be confirmed before use. No paid resource is required by this limited recipe,
but an existing approved database/access solution is not established by it.

Application authentication is not protection of the entire staging site/API.
Public landing/health/auth/demo endpoints and Render's direct origin remain an
access-control limitation. Netlify protection alone does not protect Render.
No whole-environment gate was added. Before internal exposure, inspect existing
account entitlements and agree on protection of both entry points. Any paid access
feature requires an exact quote and owner approval. Deployment secrets/access
credentials require separate authorization; none were requested or used here.
